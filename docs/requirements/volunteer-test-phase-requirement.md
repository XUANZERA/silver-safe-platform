# 志愿者测试阶段需求分析文档

## 1. 项目背景

银发安全出游辅助系统当前已经完成核心功能开发，包括：

- FastAPI 后端服务
- Web 管理端
- 微信小程序老人端
- 微信小程序家属端
- 实时定位上传
- 安全状态查询
- 定位新鲜度判断

当前系统已经能够在开发环境中完成完整流程：

老人端：
登录 → 开启定位 → 上传位置

家属端：
登录 → 查看老人安全状态和位置


但是当前版本仍属于开发演示版本：

- 后端运行在开发机器本地环境
- 小程序 API 地址依赖本地配置
- UI 包含开发调试信息
- 数据库主要用于开发验证
- 尚未经过真实用户体验验证


因此需要建立志愿者测试版本，用于收集真实用户反馈。


---

# 2. 测试阶段目标

本阶段目标：

将开发环境中的系统转换为一个可供真实志愿者使用的小规模测试系统。


具体目标：

## 2.1 可访问

志愿者可以通过微信小程序访问系统，而不依赖开发人员电脑。


## 2.2 可体验

志愿者能够完成完整用户流程：

老人：

1. 登录系统
2. 查看今日任务
3. 开启定位
4. 正常退出


家属：

1. 登录系统
2. 查看老人位置
3. 查看安全状态
4. 获取定位更新时间


## 2.3 可反馈

系统能够支持：

- 用户体验反馈
- 功能问题反馈
- 操作困难反馈


## 2.4 可维护

开发人员能够：

- 查看系统运行状态
- 定位错误原因
- 管理测试数据


---

# 3. 用户角色分析


## 3.1 老人用户

目标：

体验定位守护功能。


主要行为：

- 登录
- 同意定位权限
- 开启定位
- 日常携带手机移动


关注：

- 操作是否简单
- 是否理解定位状态
- 是否愿意授权


---

## 3.2 家属用户

目标：

体验远程查看老人安全状态。


主要行为：

- 登录
- 查看老人位置
- 查看更新时间
- 判断老人是否安全


关注：

- 信息是否清晰
- 是否产生信任


---

## 3.3 测试管理员

目标：

维护测试环境。


职责：

- 创建测试账号
- 分配测试任务
- 收集反馈
- 查看系统状态


---

# 4. 功能需求


## FR-001 用户登录

系统应支持测试账号登录。

要求：

- 使用已有 Backend 登录机制
- 不新增认证体系
- 使用 Bearer Token


验收：

用户能够成功进入对应角色页面。


---

## FR-002 老人定位功能

系统应支持老人主动开启定位守护。


要求：

- 必须经过用户主动操作
- 不允许后台自动启动
- 使用微信定位 API
- 上传原始定位数据


验收：

开启后：

- 状态显示正常
- 后端收到定位数据


---

## FR-003 家属安全查看

家属端应展示：

- 最新位置
- 更新时间
- Backend 返回安全状态


要求：

客户端不得自行计算风险。


验收：

家属能够查看老人当前安全信息。


---

## FR-004 用户反馈

测试版本需要提供反馈渠道。


反馈内容包括：

- 使用困难
- 功能异常
- 建议


---

# 5. 非功能需求


## NFR-001 稳定性

系统应保证：

- 测试期间服务持续运行
- 错误不会导致系统崩溃


---

## NFR-002 数据隔离

测试环境数据：

- 与开发数据隔离
- 与未来生产数据隔离


---

## NFR-003 隐私保护

系统不得：

- 暴露真实用户数据
- 泄露测试账号
- 保存无必要信息


---

## NFR-004 可追踪性

出现问题时：

开发人员能够定位：

- 用户操作
- API 请求
- 后端错误


---

# 6. 测试验收标准


## 功能验收

| 功能 | 标准 |
|-|-|
| 登录 | 成功进入页面 |
| 定位 | 能上传位置 |
| 家属查看 | 能看到安全状态 |
| 数据刷新 | 状态正常更新 |
| 错误处理 | 有明确提示 |


## 工程验收

- 后端部署完成
- 数据库独立
- 小程序配置完成
- 测试账号可用


## 用户验收

至少完成：

- 老人用户体验
- 家属用户体验
- 反馈收集
