# 3. 部署目标

## 核心目标

建立一个最小可用志愿者测试环境：

```

微信体验版

↓

HTTPS API Gateway

↓

FastAPI Backend

↓

Testing Database

```


支持：

- 5~20名志愿者
- 老人端测试
- 家属端测试
- GPS上传
- 安全状态查看
- 用户反馈


---

# 4. 功能需求

## FR-001 公网访问

系统必须提供公网HTTPS访问地址。

要求：

- 有效域名
- TLS证书
- 微信request合法域名


---

## FR-002 小程序连接测试环境

小程序testing配置必须指向真实Backend地址。

禁止：

- localhost
- 127.0.0.1
- HTTP地址
- 占位域名


---

## FR-003 测试数据隔离

测试环境必须独立：

- 数据库
- 密钥
- 测试账号


禁止：

测试数据进入开发数据库或生产数据库。


---

## FR-004 志愿者账号管理

系统需要支持：

- 多组老人账号
- 多组家属账号
- 独立测试任务


避免多个志愿者共享同一老人位置。


---

## FR-005 端到端测试

必须验证：

老人：

```

登录
↓
授权定位
↓
开启守护
↓
上传位置

```


家属：

```

登录
↓
查看地图
↓
查看安全状态

```


---

# 5. 非功能需求

## 安全

要求：

- DEBUG关闭
- 独立SECRET_KEY
- HTTPS传输
- 测试数据脱敏


---

## 可维护性

部署需要：

- 环境变量配置
- 启动方式说明
- 数据备份方式


---

## 性能

测试规模：

- 20用户以内

允许：

- 单实例Backend
- SQLite或轻量数据库


---

# 6. 不包含范围

本阶段不要求：

- 商业级高可用
- 多区域部署
- 自动扩缩容
- 大规模监控系统


---

# 7. 验收标准

满足以下条件：

- 微信体验版可以访问Backend
- 老人端可以上传真实定位
- 家属端可以查看安全状态
- 测试数据隔离
- 志愿者可以提交反馈

达到：
