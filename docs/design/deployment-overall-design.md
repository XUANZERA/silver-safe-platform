# 银龄安全系统（Silver Safe Platform）
# Phase 4 外部志愿者测试部署总体设计说明书

## 1. 架构总览与设计原则

### 1.1 核心设计哲学
在“外部志愿者测试准入”（Phase 4）阶段，系统架构的核心诉求是**极简、稳定、可复现、强隔离**。
* **避免过度架构（No Over-Engineering）**：坚决不引入 Kubernetes、微服务拆分、Redis 缓存或 Kafka 消息队列，将外部依赖降为零。
* **后端绝对权威（Backend Authority）**：后端是唯一的业务与安全仲裁者，前端仅作为传感器（采集 GPS）与展示终端。
* **极小运维开销（Low-Ops Burden）**：单台云主机（Linux VM）承载反向代理、应用服务与本地持久化，实现分钟级冷启动与自愈。

## 2. 核心组件职责边界

### 2.1 微信小程序客户端（Untrusted Frontend）
* **定位**：零信任端，仅作为人机交互终端。
* **职责范围**：
  * 志愿者账号登录，持有并附带 Bearer JWT Token 发起请求。
  * 经用户显式授权后，前台高频调用 `wx.getLocation` 获取高精度 GPS 经纬度（WGS84 坐标系）。
  * 周期性上报点位至后端 `/api/v1/locations`。
  * 纯粹拉取并渲染后端返回的权威状态（如地图标记、Polyline 轨迹线、`SAFE`/`ALERT` 标签）。
* **严禁行为**：
  * 禁止在前端计算老人是否超出围栏。
  * 禁止在前端判定定位是否超时或丢失（新鲜度）。
  * 禁止在前端本地缓存篡改任何状态。

### 2.2 反向代理网关（Caddy 2）
* **定位**：公网接入与安全网关。
* **职责范围**：
  * 对外监听 80 与 443 端口，对外提供合法的域名访问入口（如 `silver-test.example.com`）。
  * 全自动管理 ACME TLS 证书（申请、加载、90天自动续签）。
  * 终止 TLS 连接，将纯明文流量安全反代至本地 `127.0.0.1:8000`。
  * 提供基础的 HTTP 头部安全加固（HSTS、X-Content-Type-Options 等）。

### 2.3 FastAPI 权威后端（Single Source of Truth）
* **定位**：系统唯一权威中枢与业务计算节点。
* **职责范围**：
  * **认证与授权**：校验老人与家属身份，强制实施绑定关系校验，彻底杜绝越权。
  * **行程生命周期**：管理 Trip 状态（`created` -> `active` -> `completed` / `cancelled`）。
  * **位置存储与流转**：持久化位置日志，记录接收时间戳与采集时间戳。
  * **安全判定引擎**：
    * **时效新鲜度（Freshness）**：根据当前时间与最后有效点时间差，裁决 `FRESH`、`STALE`、`INACCURATE` 或 `NO_DATA`。
    * **电子围栏分析（Risk Assessment）**：基于 Haversine 公式计算点位与围栏中心欧氏距离，判定 `SAFE`、`PENDING` 或 `ALERT`。

### 2.4 SQLite 独立存储引擎
* **定位**：轻量级单实例关系型数据库。
* **并发策略**：
  * 采用 **WAL (Write-Ahead Logging)** 日志模式，实现“读写并发互不阻塞”。
  * 配合 Uvicorn 单 Worker 进程模型，从源头上消除了多进程并发写导致的 `database is locked` 风险。
  * 针对 10~20 名测试志愿者的低频位置上报（每 10 秒/人），单节点承载能力富余超过 50 倍。

## 3. 进程模型与运维架构

### 3.1 单 Worker 托管模型
* 运行命令：`uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1`
* **采用单 Worker 的核心理由**：
  1. SQLite 属于嵌入式文件型数据库，多进程高频并发写入是导致锁超时的主要诱因。单 Worker 串行写入能天然保障事务原子性与稳定性。
  2. 测试规模在 20 人以内，单 Python 异步进程（FastAPI + asyncio + uvloop）足以支撑每秒数百次请求，吞吐量远超实际需求。

### 3.2 systemd 系统级托管
* 后端服务由 Linux `systemd` 服务管理器统一托管。
* 具备以下特性：
  * **开机自启（Auto-start on boot）**：服务器维护重启后无须人工介入。
  * **崩溃拉起（Restart on failure）**：异常退出 5 秒内自动重启。
  * **标准化日志（Journald integration）**：所有终端日志统一由 `journalctl` 收集并支持实时滚动查看。

## 4. 环境与数据空间隔离模型

系统通过环境变量 `APP_ENV` 实现开发、测试环境的刚性隔离：

| 隔离维度 | 开发环境 (development) | 志愿者测试环境 (testing) |
| :--- | :--- | :--- |
| **触发标识** | `APP_ENV=development` | `APP_ENV=testing` |
| **数据库文件** | `data/silver_safe.db` | `/var/lib/silver-safe/testing.db` |
| **测试账号范围** | `elder01` / `family01` 等单机演示账号 | `elder_test_01~10` / `family_test_01~10` |
| **重置脚本约束** | `scripts/reset.py`（保护用户表） | `scripts/reset_testing.py`（彻底初始化10组基线） |
| **秘钥与密码** | 开发默认固定密钥 | 环境变量注入高强度随机盐与独立测试密码 |

## 5. 安全体系设计

1. **纵深防御安全域**：
   * 公网仅暴露 Caddy 端口（80/443）。
   * FastAPI（8000）绑定在 `127.0.0.1` 本地回环接口，防火墙禁止外部直连。
   * SQLite 文件存储于 `/var/lib/silver-safe/`，文件权限限制为 `600`，仅专属系统运行账号 `silver-safe` 可读写。
2. **防横向越权设计**：
   * 所有针对老人行程和位置信息的 API，强制提取 JWT 中记录的当前 `user_id`。
   * 查询必须通过 `ElderFamilyBinding` 表进行前置过滤。如果家属非该老人合法绑定监护人，直接抛出 `403 FORBIDDEN`，杜绝任何未授权的数据刺探。

## 6. 部署范围边界声明（Scope of Deployment）

* **纳入范围 (In Scope)**：
  * 单台 2C 2G/4G 云服务器环境配置；
  * Caddy 自动 HTTPS 反代与域名指向；
  * 微信小程序 `request` 合法域名配置与体验版发版；
  * 10 组多租户隔离账号、测试围栏数据生成与一键重置工具；
  * 发布前自动化验收脚本。
* **排除范围 (Out of Scope)**：
  * 分布式集群部署（K8s / Docker Swarm）；
  * 第三方短彩信网关与短信推送；
  * 微信支付与实名认证接口；
  * Elasticsearch / ELK 集中日志检索系统。
